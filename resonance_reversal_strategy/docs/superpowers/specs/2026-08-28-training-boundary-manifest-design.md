# 训练边界与交易日 Manifest 修复设计

## 1. 目标

修复离线分析器把“历史信号证据窗口”和“训练收益窗口”混为一谈的问题，并为训练期末无法形成完整 1/3/5 日结果的观察定义无未来数据的右截尾规则。

本设计只调整分析合同、manifest schema、统计样本选择和文档；不修改正式策略的 RSI、KDJ、BOLL、ATR、订单、持仓或资金逻辑。

## 2. 已确认的业务规则

用户确认：实际交易必然使用决策日前的历史数据，因此正式交易和观察的 `signal_date` 不必从 2019 年首个交易日开始。

合法示例：

```text
2018-12-28  T-1 信号日
2019-01-02  决策、下单和训练收益归属日
2019-01-02+ 观察结果日
```

该链路只使用决策时点之前的数据，不构成未来函数。

## 3. 现场证据

完整聚宽 `.3` 基线与 `.4` 候选日志显示：

- 两者均有 138 笔 FILLED 订单，逐笔路径完全一致；
- 两者均有 8,808 条正式共振决策，逐条一致；
- 两者均有 730 条组合汇总，逐日一致；
- 期末资产均为 23,856.40；
- `.4` 有 878 个相对观察；
- 5 个训练期末观察无法在 2021-12-31 前取得全部 1/3/5 日结果，共缺 10 个相对结果；
- 4 个正式观察同样缺少期末结果；
- 当前分析器还会错误拒绝 2018-12-28 的信号、事件和有效期证据。

因此，策略旁路非干扰已经得到平台证据支持，但现有分析器的日期合同无法处理真实训练首尾边界。

## 4. 范围契约

### 4.1 允许改变

- 独立交易日 manifest 的 schema 与覆盖范围；
- 分析器按日期角色选择验证窗口；
- 右截尾识别、报告和完整样本统计；
- 分析器报告中的日历与样本元数据；
- 对应测试、README 和策略规格说明。

### 4.2 必须保持不变

- `.3` 正式逻辑指纹、参数指纹和 ETF 池指纹；
- `.4` 相对观察逻辑指纹；
- 138 笔订单基线与 23,856.40 期末资产基线；
- RSI(14)、KDJ(9,3,3)、BOLL(20,2)、ATR(14,2.5)；
- BOLL 必选的正式共振规则；
- 09:35 执行、T-1 信号、ATR 优先、持仓和资金逻辑；
- 现有分析门槛数值。

### 4.3 不得传播到

- 2022 及以后验证期数据；
- 相对观察直接下单；
- 参数、阈值、ETF 或共振窗口搜索；
- PTrade、其他策略或本地行情数据；
- 聚宽策略运行代码。

## 5. 方案比较

### 方案 A：日历证据窗口与收益窗口分离（采用）

manifest 覆盖 2018–2021，内部显式声明 2019–2021 为收益窗口。分析器按字段角色选择窗口，并对期末完整观察样本做预注册右截尾。

优点：因果正确、无需读取 2022、无需让策略知道实验结束日、保留订单基线。

### 方案 B：两个独立 manifest

分别提供预热日历和训练日历。边界清晰，但增加 CLI、hash、文件别名和运维复杂度，没有必要。

### 方案 C：策略在期初/期末禁止信号

会改变正式订单和期末资产，还让交易策略耦合研究窗口，拒绝采用。

## 6. Manifest Schema V2

manifest 必须是 UTF-8 JSON，严格只含以下字段：

```json
{
  "schema_version": 2,
  "market": "XSHG",
  "calendar_coverage_start": "2018-01-01",
  "calendar_coverage_end": "2021-12-31",
  "evaluation_start": "2019-01-01",
  "evaluation_end": "2021-12-31",
  "source": "JoinQuant get_all_trade_days",
  "sessions": []
}
```

约束：

- `sessions` 必须包含覆盖期内全部聚宽交易日，严格递增且不重复；
- schema V1 不再作为本轮正式输入，避免窗口语义歧义；
- 仍按原始 bytes 计算并预先冻结小写 SHA-256；
- 文件大小、重复键、有限 JSON、路径别名、输入输出物理隔离规则保持不变；
- CLI 参数名保持 `--session-calendar` 与 `--session-calendar-sha256` 不变。

## 7. 日期角色合同

| 日期角色 | 合法窗口 | 额外约束 |
|---|---|---|
| 指标历史数据 | 日历证据窗口 | 必须早于决策时点 |
| `signal_date` | 日历证据窗口 | 必须是决策日的前一交易日 |
| supporter/event 日期 | 日历证据窗口 | 必须符合两交易日共振生命周期 |
| `expires_date` | 日历证据窗口 | 必须符合生产事件有效期算法 |
| 决策日、日志日、订单日 | 训练收益窗口 | 不得落入 2018 或 2022 |
| 组合汇总日 | 训练收益窗口 | 必须覆盖完整 2019–2021 交易日 |
| 观察 closing date | 训练收益窗口 | 必须是 manifest 推导出的精确 horizon 日 |

训练年度归属使用观察注册/决策日志日，不再使用可能位于上一自然年的 `signal_date`。
组合汇总 session 只与 manifest 中 `evaluation_start..evaluation_end` 的子集比较，不能要求
策略为 2018 预热 session 生成组合汇总。

## 8. 右截尾合同

### 8.1 定义

对每个正式或相对观察，使用 manifest 从 `signal_date` 推导 H1、H3、H5 的精确 closing session。

若任一必需 closing session 晚于 `evaluation_end` 或不存在于 manifest，则该观察为 `RIGHT_CENSORED`。

### 8.2 完整样本原则

- 统计门槛只使用同时具备 H1、H3、H5 的完整观察；
- 一个观察一旦右截尾，就从全部 horizon 的收益汇总中排除，避免不同 horizon 使用不同样本；
- `candidate_count`、年度计数、方向计数、ETF 贡献和分支统计均使用完整样本；
- 右截尾判断只依赖冻结日历和注册日期，不读取收益值。

### 8.3 数据质量

- 右截尾导致的缺失结果不是数据质量错误；
- 报告必须分别给出正式/相对的注册总数、完整样本数和右截尾数；
- 已经存在且位于训练窗口内的部分 horizon 结果仍需严格校验，但不进入统计；
- 完整样本缺少任何结果仍然 fail closed；
- 任何 2022 结果一律拒绝，不能用于补齐右截尾。

## 9. 分析器处理流程

```text
验证 schema V2 与原始 bytes hash
  → 建立 2018–2021 日历证据窗口
  → 建立 2019–2021 训练收益窗口
  → 审计初始化、信号、事件、决策、订单和组合日期角色
  → 验证 .3/.4 正式订单路径与期末资产
  → 识别完整观察与 RIGHT_CENSORED
  → 仅对完整观察计算固定门槛
  → 输出数据质量、截尾数量和门槛结果
```

## 10. 控制流真值表

| 场景 | 是否进入收益统计 | 是否数据质量失败 | 正式订单比较 |
|---|---:|---:|---:|
| 2018 信号、2019 决策、完整 H1/H3/H5 | 是 | 否 | 保持 |
| 2018 决策或订单 | 否 | 是 | 失败 |
| 2019–2021 信号且结果完整 | 是 | 否 | 保持 |
| 期末右截尾 | 否 | 否，单独报告 | 保持 |
| 完整样本缺结果 | 否 | 是 | 保持 |
| 使用 2022 补结果 | 否 | 是 | 保持 |
| `.3/.4` 订单路径不同 | 不影响判断 | 是 | 失败 |

本设计不新增影响策略交易的布尔参数或模式开关。

## 11. 报告合同

`session_calendar` 增加：

- `schema_version=2`；
- `calendar_coverage_start/end`；
- `evaluation_start/end`；
- `session_count`；
- 原始 bytes 的小写 `sha256`。

`data_quality` 增加：

- `relative_registration_count`；
- `relative_complete_count`；
- `relative_right_censored_count`；
- `formal_registration_count`；
- `formal_complete_count`；
- `formal_right_censored_count`。

现有门槛名称和阈值保持不变，但样本基数改为完整观察集合。

## 12. 测试要求

必须先写失败测试，再修改实现，至少覆盖：

1. schema V2 合法 manifest；
2. V1、错误覆盖、hash、重复键、路径别名继续失败；
3. 2018-12-28 信号 + 2019-01-02 决策合法；
4. 2018 决策/订单仍失败；
5. 年度归属使用2019注册日而不是2018信号日；
6. 训练期末完整 H5 不可推导时标记右截尾；
7. 右截尾缺结果不产生数据质量错误；
8. 右截尾已有的 H1/H3 结果被校验但不计入统计；
9. 完整样本缺结果仍失败；
10. 2022结果仍失败；
11. 现有测试夹具继续冻结138笔订单和23,856.40期末资产；
12. 分析器不读行情、不下单、不搜索参数。

真实平台交付另行逐条比较 `.3/.4` 的138笔订单、8,808条正式决策和730条组合记录；
这些大体量真实日志不得复制进单元测试或成为测试对附件路径的依赖。

## 14. 平台交付顺序

当前已查看的 `.3/.4` 日志只保留为诊断证据，不作为最终预注册结果。

正式顺序：

1. 实现并验证 schema V2 与右截尾规则；
2. 在独立聚宽研究环境导出 2018–2021 schema V2 manifest；
3. 保存文件并预先冻结其原始 bytes SHA-256；
4. 不改策略参数，重新运行 `.3` 和 `.4` 的 2019–2021 回放；
5. 执行只读分析器；
6. 只有数据质量和固定相对观察门槛全部通过，才能提出下一份候选规格。

## 15. 非目标与剩余结论

- 本修复不改善当前正式策略约 -19.06% 最大回撤和 2021 年约 -12.98% 表现；
- 本修复不代表训练期总体策略门槛通过；
- 不允许因相对买入表现较好而直接删除卖出分支或启用真实下单；
- 不进入2022验证期，不准备实盘。

## 16. 验收标准

- 2018历史信号可以作为2019决策的因果证据；
- 2018决策、订单和收益仍被拒绝；
- 期末右截尾不再被误报为日志损坏；
- 完整样本的任何缺失继续 fail closed；
- 不读取2022数据；
- 正式订单与资产基线不变；
- 仅批准的分析器、测试和文档文件发生变化。
