# PTrade 前瞻实盘日志归档协议

本协议从 **2026-07-18** 起生效。它只建立未来实盘证据的来源链，不是新策略实验，也不授权修改 `cross-v0.3.2`。

## 1. 冻结身份

- 策略版本：`cross-v0.3.2`
- 部署构建：`20260720.2`
- 业务配置指纹：`1506a0e834fe`
- 协议开始日：`2026-07-18`

归档器会先运行正式发布核验，再核对每份日志中的版本、构建和业务配置指纹。身份缺失、身份混杂、指纹不符或包含协议开始日前记录的文件一律拒绝。

## 2. 不影响交易的边界

本实现：

- 不改变交易逻辑、ETF 池、指标、阈值、持仓或止损；
- 不新增定时任务，仍只有正式 PTrade 的 09:35 主流程和 10:35 复牌补偿；
- 不新增行情请求，不调用 PTrade 行情、持仓、订单或交割单 API；
- 不修改正式 JoinQuant、PTrade 或本地主线策略文件；
- 不计算收益、胜率、价格改善、信号质量或任何行情统计。

它只读取用户以后主动导出的 PTrade 原始日志，记录文件哈希、时间边界、执行日/信号日以及买卖委托、成交回报、IOPV 观察和复牌补偿的事件数量。

## 3. 只增不改的归档

每份通过校验的日志按原始字节计算 SHA256，并保存为：

```text
<归档目录>/raw/<sha256>.log
```

清单保存在：

```text
<归档目录>/manifest.json
```

相同内容重复归档是幂等的；同一哈希对应的原始字节不同则立即报错。源日志不会被修改或删除。归档目录应独立于源日志目录，并作为私有运行资料保存，因为原始日志可能包含账户运营信息。

## 4. 使用方法

PTrade 导出日志后，在仓库根目录运行：

```powershell
python cross_signal_strategy/tools/archive_ptrade_forward_logs.py `
  --archive-root G:\financial\history_data\cross_signal_forward_live_logs `
  C:\path\to\ptrade-export.log
```

一次可以提供多个日志路径。日志必须包含 `[发布指纹]` 和至少一条正式执行记录；只有零散截图、手工摘录或缺少初始化身份的片段不能进入正式归档。

## 5. 防止事后挑选

归档本身不开放研究预算。将来若要研究某个实盘问题，必须按以下顺序：

1. 先登记假设、因果机制、允许字段、样本起点、成功/失败门槛和停止规则；
2. 登记前已经归档的日志最多作为问题发现材料，不得伪装成独立验证；
3. 登记后新产生且连续归档的日志才可作为独立确认样本；
4. 不得删除不利日期、失败委托、停牌日或无交易日；
5. 不得用于验证期调参，也不得根据验证期或全周期结果选择指标、阈值、时间点或 ETF 例外；
6. 只有独立确认样本通过预先冻结的门槛，才可以另行申请一个候选研究预算。

因此，现在可以持续积累证据，但不能边看结果边修改规则。这个边界正是前瞻记录比继续回挖 2019-2021 更有价值的地方。

## 6. 当前结论

正式策略继续冻结。归档器只提高未来问题的可追溯性，不能证明策略更优，也不能替代聚宽回测、PTrade 委托核对或未来单独登记的实验。
