# Cross-Signal 胜率非劣优化设计

日期：2026-09-02
状态：已在对话中分节确认，等待实施计划
目标策略：`cross-v0.3.3` 及其冻结研究候选

## 1. 目标与成功定义

本次研究只完成已经冻结的 `late-veto + early-pre-MACD` 候选，不创建新指标、
新参数组合或相邻阈值实验。目标是在不降低收益、不扩大最大回撤的前提下，
提高聚宽口径的已平仓交易胜率。

胜率沿用现有聚宽已平仓交易口径，未平仓持仓不计入胜率。正式版与候选版必须
采用相同回测窗口、初始资金、手续费、滑点、回测频率和平台配置进行配对比较。

硬性成功条件如下：

- 每个验证窗口的总收益率不得低于同窗口正式版。
- 每个验证窗口的最大回撤不得高于同窗口正式版。
- 每个验证窗口的已平仓胜率不得低于同窗口正式版。
- 2019—2021 训练期和最终全周期的胜率均须至少提高 3 个百分点。
- 不允许用单笔交易造成的偶然胜率变化作为采纳依据。
- 验证期结果只能检验冻结规则，不得用于修改、选择或重开规则。

## 2. 范围契约

**目标对象：** 尚未持有、准备进入新买入队列的 ETF 候选。

**目标处理阶段：** 使用 T-1 及更早日线完成全池评分，并完成现有持仓卖出处理后，
在 T 日 09:35 创建新买入订单之前。

**允许改变的行为：**

1. 对满足原正式买入门槛但属于冻结 late-MACD/BOLL-upper 形态的候选执行 veto。
2. 在全部合格 primary 候选之后，用满足冻结 early-pre-MACD 条件的 50—59 分候选
   填补剩余持仓槽位。

**必须保持不变：**

- 正式卖出评分、价格确认、ADX 保护、ATR 止损及组合 ATR 压力控制。
- 五日最短持有、仓位计算、ETF 池、primary 内部排序和最大持仓数。
- T 日 09:35 执行时点以及信号只使用 T-1 及以前数据的因果边界。
- 正式版不满足目标规则的买入路径和所有非目标候选的处理方式。

**不得传播到：**

- `smart_trade_joinquant_cross_signal_etf.py` 正式主文件，除非全部门禁通过且另行确认采纳。
- PTrade 正式策略、IOPV 路径、其他 ETF 策略或其他研究族。
- 卖出资格、持仓清理、数据源选择、验证期调参或其他业务阶段。

## 3. 冻结候选规则

候选文件：
`smart_trade_joinquant_cross_signal_etf_late_veto_early_pre_macd_candidate.py`

- 版本：`cross-v0.3.3-late-veto-early-pre-macd-candidate`
- 构建号：`20260822.3-candidate`
- 指纹：`f6b08195dd3d`

### 3.1 Late veto

一个原本符合正式 primary 买入资格的候选，只有同时满足以下条件时才被 veto：

- 当前存在 MACD 金叉，且金叉年龄为 0；
- RSI 多头组方向向上，活跃 RSI 金叉年龄为 1 或 2；
- 活跃 KDJ 金叉年龄为 1 或 2；
- T-1 收盘价大于等于 BOLL 上轨。

### 3.2 Early pre-MACD

一个候选只有同时满足以下条件时才进入 early 队列：

- `50 <= buy_score < 60`；
- 保留正式版 `buy_allowed`；
- RSI 多头组方向向上，活跃 RSI 金叉年龄为 0 或 1；
- 活跃 KDJ 金叉年龄为 0 或 1；
- 尚未发生 MACD 金叉；
- `DIF - DEA < 0`，且本期负向差值比上一期收窄；
- T-1 收盘价严格低于 BOLL 上轨；
- `RSI6 < 85`；
- `sell_score < 30`；
- 保留正式版新买入位置保护和 blocked-combo 保护；
- 当前未持有该 ETF，也不在当日卖出排除集合中。

### 3.3 队列与控制流真值表

| 输入状态 | 是否进入 primary | 是否进入 early | 结果 |
|---|---:|---:|---|
| 符合正式买入且不命中 late veto | 是 | 否 | 按正式排序进入 primary |
| 符合正式买入且命中 late veto | 否 | 否 | 排除并记录 veto 日志 |
| 不满 60 分但完整满足 early 条件 | 否 | 是 | 排在全部 primary 之后，只补剩余槽位 |
| 其他情况 | 否 | 否 | 保持不买入 |

primary 与 early 的分数区间互斥。`entry_channel` 只用于标记日志，不得控制卖出、
仓位、资源清理或任何其他业务行为。

## 4. 验证顺序与硬门禁

所有指标比较使用原始精度值，不能以页面四舍五入数字判定临界结果。任一阶段失败
立即停止，记录并拒绝候选，不得根据结果修改规则后重新尝试。

### 4.1 2019—2021 训练期

先且仅先运行该窗口。已记录正式基线为：

- 总收益率：+129.25%
- 最大回撤：6.28%
- 已平仓胜率：约 55.8%（53 胜、42 负）
- 盈亏比：5.297

候选必须同时满足：

- 总收益率不低于 +129.25%；
- 最大回撤不高于 6.28%；
- 已平仓胜率至少达到约 58.8%，并高于正式版和失败的单独 late-veto 候选；
- early-pre-MACD 实际成交不少于 3 笔，且覆盖至少 2 个自然年；
- 正收益转亏损平仓数量不得高于正式版；
- 盈亏比不低于 3.0；
- 2019、2020、2021 每个自然年收益均为正。

为消除平台或数据漂移，正式判定优先使用同配置现场重跑的正式版配对结果；上述已记录
基线用于身份核对和异常检测。若现场正式版与已记录值不一致，先查明原因，不直接比较。

### 4.2 双倍交易摩擦

只有训练期名义门禁全部通过后，才在训练期对正式版和候选版同时使用双倍手续费与
滑点。候选版的收益率、最大回撤和已平仓胜率仍须分别不劣于双倍摩擦正式版。

### 4.3 冻结验证窗口

名义和双倍摩擦训练门禁通过后，依次运行：

1. 2022—2023；
2. 2024—双方统一的最新截止日；
3. 2015—2018；
4. 2010—2014。

每个窗口均重新配对运行正式版与候选版，并同时满足收益率不低、最大回撤不高、
已平仓胜率不低。2010—2014 ETF 池不完整的事实必须披露，但不能据此放宽门槛。

现有记录仅作为交叉检查：

| 窗口 | 正式版收益率 | 正式版最大回撤 | 正式版胜率 |
|---|---:|---:|---:|
| 2022—2023 | +17.90% | 11.17% | 38.5% |
| 2024—当前记录截止日 | +58.17% | 9.98% | 51.3% |
| 2015—2018 | +23.21% | 7.38% | 44.4% |
| 2010—2014 | +1.20% | 5.23% | 36.6% |

### 4.4 最终全周期

全部独立窗口通过后，才运行最终全周期。由于当前没有同截止日、同配置的可靠全周期
基线，必须现场同时运行正式版与候选版。候选版必须满足：

- 总收益率不低于配对正式版；
- 最大回撤不高于配对正式版；
- 已平仓胜率至少高出配对正式版 3 个百分点。

## 5. 回测证据与结果记录

每一组聚宽配对回测必须保存：

- 策略版本、构建号、指纹和运行时间；
- 起止日期、初始资金、手续费、滑点、回测频率和执行时点；
- 总收益、最大回撤、已平仓胜率、盈亏比和逐年收益；
- 买卖成交明细和完整策略日志；
- late-veto 触发数量；
- early-pre-MACD 入选数量、实际成交数量及覆盖年份；
- 正收益转亏损平仓数量；
- 同一窗口正式版与候选版的配对判定表。

未平仓持仓不得混入胜率。页面汇总、成交明细和日志之间如有数量矛盾，先定位口径或
数据问题；在原因明确前不作通过结论。

## 6. 异常与停止条件

- 指纹、日期、资金、费用、滑点或回测配置不一致：该配对无效，重新运行。
- early 成交少于 3 笔或覆盖少于 2 年：按样本不足拒绝，不放宽条件。
- 缺少成交明细、完整日志或关键指标：结果不完整，不得判定通过。
- 本地批准的 `G:` 训练或 warm-up 数据根不存在：明确记录本地验证阻塞，不得换用
  验证期、全周期或其他未授权行情源。
- 任一窗口失败：停止后续流程，记录失败原因并关闭候选，不允许相邻阈值或补偿规则。
- 全部门槛通过：只形成正式采纳方案，不自动修改正式 JoinQuant 或 PTrade 文件。

## 7. 实施与测试边界

后续实施计划仅允许：

1. 保持冻结候选源码及指纹不变；
2. 将 `research_budget.json` 和 `research_budget.md` 的旧 95% 收益保留门槛收紧为本设计；
3. 增加候选门禁、规则边界、primary 优先、early 仅补位及非目标路径测试；
4. 编写聚宽配对运行清单和结果模板；
5. 在得到真实聚宽结果后，按通过或拒绝路径更新研究记录。

测试至少覆盖：

- early 每个条件的正例、边界和反例；
- late veto 的完整命中及缺少任一条件时不命中；
- primary 始终排在 early 前，early 不得挤掉 primary；
- 已持有、当日已卖出、卖出分数、位置保护和 blocked-combo 仍阻止 early 买入；
- 正式卖出、ATR、仓位和 T-1 数据边界不因 `entry_channel` 改变；
- 版本、构建号和指纹检查。

当前完整测试套件中已知的 `G:` 数据缺失和历史测试硬编码实验数量问题必须单独报告，
不得在本次策略规则工作中顺手修改。静态检查、聚焦单元测试、本地数据测试和聚宽真实
回测必须分别陈述，不能用其中一种代替另一种。

## 8. 非目标与采纳边界

本设计不承诺候选一定能够达到目标，也不允许通过优化搜索保证结果。它只定义一条已经
冻结、可证伪的研究路径和严格非劣门槛。

候选失败时，`cross-v0.3.3` 保持正式版本；候选全部通过时，也必须先提交独立的正式
采纳设计，说明 JoinQuant 主文件合并、版本升级、PTrade 同步和平台验证范围，再由用户
确认后实施。
